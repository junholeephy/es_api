### 2.7 이 단계에서 찾아 고친 결함 (3건)

속성 기반 테스트를 **반복 실행**하면서 나왔습니다. 매번 다른 입력을 만들기 때문에
한 번 통과했다고 끝이 아니며, 실제로 5회차·8회차에서 새 결함이 드러났습니다.

| # | 결함 | 영향 | 조치 |
|---|---|---|---|
| 1 | `TimeWindow` 가 두 끝의 UTC 오프셋이 같기를 요구 | 서머타임을 넘는 구간이 통째로 거부됨 | 불변식 TW-4 철회 + 회귀 테스트 |
| 2 | 구간 분할이 **벽시계 산술** | 서머타임이 끝나는 날 한 조각이 **두 시간**을 덮는데 `duration` 은 한 시간이라고 답함. 제약 C-3(조회당 24시간 상한)이 무력화 | `chunks()`·`duration`·TW-3 을 절대 시간 기준으로 변경 + 회귀 테스트 2개 |
| 3 | `slug` 가 **분까지만** 담음 | `05:00:00` 과 `05:00:01` 에 끝나는 두 조각이 같은 파일명 → 기록엔 둘 다 완료, 파일은 하나. **CQ1=A 로 막으려던 바로 그 실패** | `slug` 를 `key.replace(":", "")` 로 파생 + 회귀 테스트 2개 |

**결함 2와 3은 조용히 틀리는 종류입니다** — 프로그램은 정상 종료하고 로그도 깨끗합니다.
예시 테스트로는 "서머타임이 끝나는 날 1시간 단위로 자르기"나 "5시간 1초짜리 범위" 같은
입력을 떠올리기 어렵습니다.

파일명 형식이 바뀌었습니다: `data-2026-09-09T1800+0900` → `data-2026-09-09T180000+0900`.
`slug` 를 `key` 에서 파생시켰으므로, **키가 다르면 이름도 반드시 다릅니다**.

기본 타임존 `Asia/Seoul` 에는 서머타임이 없어 결함 1·2 는 주 사용 경로에 영향이
없었습니다. 결함 3 은 `--from/--to` 에 초를 적으면 기본 설정에서도 재현됩니다.
