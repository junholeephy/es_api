## ⚠️ 발견된 문제: 출력 파일명 충돌

`TimeWindow.label`(= 파일명의 날짜)은 **창의 종료 날짜**입니다. 그런데 Q2=C로 임의 시각이 허용되면서,
**서로 다른 창이 같은 파일명을 갖는** 경우가 생깁니다.

**예시 1 — 시각이 다른 두 실행**
```
[2026-09-01T18:00, 2026-09-02T18:00)  -> label 2026-09-02 -> data-2026-09-02.jsonl
[2026-09-01T03:00, 2026-09-02T03:00)  -> label 2026-09-02 -> data-2026-09-02.jsonl  (충돌)
```

**예시 2 — 청크 크기를 6시간으로 설정 (FR-2가 허용)**
```
[09-02T00:00, 09-02T06:00) -> 2026-09-02
[09-02T06:00, 09-02T12:00) -> 2026-09-02
[09-02T12:00, 09-02T18:00) -> 2026-09-02   하루에 4번 같은 이름
[09-02T18:00, 09-03T00:00) -> 2026-09-03
```

체크포인트 키는 ISO 종료 시각이라 충돌하지 않습니다(Application Design Q8=A).
따라서 **체크포인트는 "4개 청크 모두 완료"라고 기록하는데 파일은 1개만 남는** 상태가 됩니다.
조용히 덮어써지므로 로그만으로는 알 수 없습니다.

## Clarification Question 1
출력 파일명을 어떻게 정할까요?

A) **항상 종료 시각 전체를 파일명에 사용** — `data-2026-09-02T180000.jsonl`
   충돌이 원천적으로 불가능. 다만 매일 실행되는 정상 경로에서도 파일명이 길어짐

B) **종료 날짜 유지 + 충돌 시 오류로 중단** — `data-2026-09-02.jsonl`.
   같은 이름이 이미 있고 창이 다르면 실행을 멈추고 알림. 파일명은 짧게 유지되고, 조용한 덮어쓰기는 없음

C) **조건부 접미사** — 창이 정확히 24시간이고 종료 시각이 `anchor_time`과 같으면 `data-2026-09-02.jsonl`,
   그 외에는 `data-2026-09-02T030000.jsonl` 처럼 시각 접미사를 붙임.
   일상적인 스케줄 실행은 짧은 이름, 예외적인 경우만 긴 이름

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: A
