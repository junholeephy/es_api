## Question 1 — `--from` / `--to` 날짜의 해석 ⚠️ 중요

D-1로 하루의 경계가 **18:00**이 되면서, "날짜"만 주면 어느 창을 뜻하는지 애매해졌습니다.

`--from 2026-09-01 --to 2026-09-03` 이 어떤 창들을 뜻해야 할까요?

A) **종료 날짜(label) 기준** — `label`이 09-01, 09-02, 09-03인 창 3개.
   즉 `[08-31 18:00, 09-01 18:00)`, `[09-01 18:00, 09-02 18:00)`, `[09-02 18:00, 09-03 18:00)`.
   출력 파일은 `data-2026-09-01.csv` ~ `data-2026-09-03.csv`. **파일명과 인자가 그대로 일치**

B) **시작 시각 기준** — `[09-01 18:00, 09-02 18:00)`, `[09-02 18:00, 09-03 18:00)`,
   `[09-03 18:00, 09-04 18:00)` 창 3개.
   출력 파일은 `data-2026-09-02.csv` ~ `data-2026-09-04.csv`. **인자와 파일명이 하루씩 어긋남**

C) **명시적 시각 입력만 허용** — 날짜만 주는 것을 금지하고 `2026-09-01T18:00` 형태를 요구

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: C

## Question 2 — anchor에 정렬되지 않는 시각을 준 경우

`--from 2026-09-01T03:00` 처럼 anchor(18:00)에 맞지 않는 시각을 주면 어떻게 할까요?

A) **오류로 거부** — anchor에 정렬된 시각만 허용. 경계가 항상 예측 가능해짐

B) **바깥으로 확장(내림/올림)** — 시작은 이전 anchor로 내리고 종료는 다음 anchor로 올림.
   요청 범위를 반드시 **포함**하되 청크는 항상 정렬됨 (데이터가 더 나올 수 있음)

C) **준 시각 그대로 사용** — anchor 무시하고 요청 시각부터 24시간씩 자름.
   경계가 파일명·체크포인트 키와 어긋날 수 있음

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: C

## Question 3 — 컬럼 경로의 기준점
설정에 컬럼을 `user.name` 이라고 적었을 때, 어디부터의 경로인가요?

A) **`_source` 내부 기준** — `user.name` 은 `hit['_source']['user']['name']`.
   메타데이터가 필요하면 `_id`, `_index` 처럼 특별 취급되는 이름을 따로 인식

B) **히트 전체 기준** — `_source.user.name` 처럼 항상 전체 경로를 적음. 규칙이 하나뿐이라 단순하지만 장황함

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: A

## Question 4 — 선택한 컬럼의 값이 배열이나 객체일 때
CQ5에서 "배열을 구분자로 합치기(D)"는 고르지 않으셨습니다.
그런데 지정한 컬럼의 값이 리스트나 dict일 수 있습니다. 어떻게 할까요?

A) **JSON 문자열로 직렬화** — `["a","b"]` -> `["a", "b"]` 문자열 그대로 CSV 셀에 기록.
   정보 손실이 없고, 나중에 다시 파싱 가능

B) **구분자로 합치기** — 배열은 `a|b` 로, 객체는 JSON 문자열로

C) **오류 처리** — 스칼라가 아닌 값이 나오면 해당 문서를 실패로 기록

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: A

## Question 6 — 문서가 0건인 청크
해당 시간대에 데이터가 하나도 없는 날은 어떻게 처리할까요?

A) **빈 JSONL 파일을 만들고 완료(done) 처리** — "확인했고 데이터가 없었다"가 기록으로 남음.
   재실행 시 다시 조회하지 않음

B) **파일을 만들지 않고 완료 처리** — 체크포인트에만 `doc_count: 0`으로 남김.
   빈 파일이 쌓이지 않지만, 파일만 보면 "안 돌린 날"과 구분이 안 됨

C) **실패로 처리** — 데이터가 없는 것은 비정상이므로 알림 대상

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: A

## Question 7 — 실패한 청크의 재시도 정책
체크포인트에 `failed`로 기록된 청크를, 다음 `extract` 실행 시 어떻게 할까요?

A) **자동 재시도** — 범위 안에 들어오면 다시 시도. 매일 실행되므로 일시적 장애가 자연히 복구됨
   (단, 계속 실패하는 청크는 매번 재시도되어 시간을 소모)

B) **건너뜀** — `failed`도 처리된 것으로 보고 넘어감. `--retry-failed` 플래그를 줄 때만 재시도

C) **재시도 횟수 제한** — 자동 재시도하되 누적 실패 횟수가 N회를 넘으면 건너뜀

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: A

## Question 8 — JSONL에 저장할 범위
"ES 원본 보존"(FR-4)에서 무엇을 한 줄로 저장할까요?

A) **히트 객체 전체** — `{"_index":..., "_id":..., "_score":..., "_source":{...}}`.
   `_id` 로 중복 제거나 추적이 가능하고, 원본 그대로임

B) **`_source`만** — `{...}` 문서 본문만. 파일이 작고 다루기 쉽지만 `_id`를 잃음

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: A

## Question 9 — CSV 출력 형식
CSV 파일의 인코딩과 헤더를 어떻게 할까요?

A) **UTF-8 + 헤더 행 포함** — 표준적. 다만 Excel에서 한글이 깨질 수 있음

B) **UTF-8 BOM(`utf-8-sig`) + 헤더 행 포함** — Excel에서 한글이 바로 열림.
   pandas 등에서도 문제없이 읽힘

C) **UTF-8 + 헤더 없음** — 다른 파이프라인에 그대로 밀어넣는 경우

X) Other (아래 [Answer]: 뒤에 직접 설명해 주세요)

[Answer]: B
